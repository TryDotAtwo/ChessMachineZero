# Matrix Trace Explorer — design

## Назначение

GitHub Pages должен быть не рекламным лендингом и не пересказом диалога, а
проверяемым интерактивным инспектором вычислений ChessMachineZero. Посетитель
должен иметь возможность пройти весь inference и собственноручно проверить,
что каждый runtime-переход получен матричными операциями и deterministic
hardmax.

## Честная граница

Сайт показывает только реально сохранённую и проверяемую трассу текущего
pawn-rule slice. Он явно сообщает, что полные шахматы ещё не реализованы.
Декоративные числа, фиктивные матрицы и утверждения о готовых полных шахматах
запрещены.

## Основной экран

Первый экран — рабочая область трассы без маркетингового hero и без текста,
похожего на ответы пользователю. На нём находятся:

- выбор inference-перехода и одной из 15 стадий;
- доска до и после выбранного перехода;
- цепочка `X → Q/K/V → QKᵀ+M → hardmax → AV → write → X′`;
- кнопки назад, вперёд, воспроизведение, пауза и сброс;
- текущие query-token, winning key, значение и изменённые выходные признаки.

## Инспектор матриц

Каждая операция открывает численную матрицу с точными размерами и значениями:

- `X`, `Wq`, `Wk`, `Wv`;
- `Q=XWq`, `K=XWk`, `V=XWv`;
- `S=QKᵀ+M`;
- `A=one_hot(argmax(S))` с правилом выбора минимального индекса при равенстве;
- `Y=AV`;
- матрицы записи `R`, `C` и `X′=X+R(Y−X)C`.

Большие матрицы сначала показываются как виртуализированная таблица/тепловая
карта, но имеют режим полного просмотра всех ячеек. Фильтрация лишь меняет
представление и никогда не подменяет исходные данные.

## Проверка отдельной ячейки

Клик по ячейке результата раскрывает арифметику:

`result[i,j] = Σₖ left[i,k] × right[k,j]`.

Показываются все ненулевые слагаемые, промежуточная сумма, маска, winning key и
hardmax tie-break. Для write-проекции аналогично раскрываются обе матричные
операции и итоговая дельта конкретной ячейки `X′`.

## Трасса токена

Режим «Путь токена» выбирает строку `X` и подсвечивает её прохождение через
Q/K/V, score, hardmax, AV и запись. Можно переключаться между:

- всеми токенами;
- активными query rows;
- winning key/value rows;
- изменившимися выходными ячейками.

## Источник данных

Числа загружаются из версионированного trace-артефакта, экспортированного из
того же frozen ProgramImage, который проходит native exact tests. Артефакт
содержит schema/version, commit, stage, token labels, shapes, sparse entries,
winners и board diff. Сайт не вычисляет шахматную легальность JavaScript-кодом;
он только воспроизводит и проверяет сохранённую матричную трассу.

CI проверяет schema, хэш/commit provenance, формулы на выбранных и граничных
ячейках, hardmax winners, board diff и соответствие публичных claims исходному
коду.

## Визуальная система

Тёмная техническая рабочая область, моноширинные числа, нейтральные границы,
cyan для текущего потока и amber только для hardmax-победителя. Основная
структура — таблицы, canvas и панели инспектора, без декоративных карточек,
маркетинговых секций и вымышленных метрик. Анимация следует потоку данных и
отключается через `prefers-reduced-motion`.

## Адаптивность и доступность

На desktop одновременно видны pipeline, матрица и арифметический инспектор.
На mobile они становятся последовательными вкладками без потери полного
просмотра. Все ячейки доступны с клавиатуры, состояния имеют текстовые метки,
а цвет не является единственным носителем смысла.

## Приёмка

- На странице нет истории запросов, ответов пользователю или маркетингового
  hero.
- Все отображаемые числа происходят из trace-артефакта с provenance.
- Каждая стадия и каждая операция раскрываются до численной матрицы.
- Для выбранной ячейки видна полная арифметика произведения и суммы.
- Hardmax winner и tie-break проверяемы по score row.
- Board diff выводится из `X′`, а не рассчитывается шахматным JS-кодом.
- Desktop и mobile core workflow проходят browser-тест.
- Public evidence gate продолжает блокировать ложное утверждение о полных
  шахматах.
