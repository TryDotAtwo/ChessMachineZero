- RED Python: `vm_compiler.hullkv` was absent.
- RED C++: `cmz/hullkv.h` was absent.
- RED exactness regression: an outer-hull-only cache failed dense top-k equivalence for the zero-query stable prefix; nested metadata was corrected to retain the first `k` indices.
- GREEN Python: 25 tests passed, including deterministic 128-query dense equivalence over 96 keys, four convex layers, an interior population, a duplicate key, and a zero query.
- GREEN C++/CUDA: `hullkv.cu`, its custom-autograd wrapper, and the native test compiled and linked against LibTorch/CUDA; the executable returned status `0` on the real CUDA device.
- Hard forward performs exact FP32 2D dot products only over artifact-precomputed nested-hull candidates and resolves ties by lowest original key index.
- The nested builder retains all original indices for duplicate quantized coordinates, so FP4 collisions preserve dense stable top-k semantics.
- Backward materializes only `[query_count, competitor_count]`, uses a floating softmax surrogate over exact selected competitors, and produced finite nonzero gradients for Q, K, and V.
- Production HullKV sources contain no detach, item, CPU transfer, host argmax, or dense `Q x K^T` operation.
